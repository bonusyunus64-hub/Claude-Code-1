## NEW FINDING — `stats.eligible` under-reports on an aborted run

The summary printed `Eligible (genres: [] at the start): 199` while 797 artists are genre-less.
That is not a data problem. `stats.eligible` is incremented **inside the walk loop**
(`scripts/backfill-genres.mjs:899`), so an abort truncates it: it counts only what the walk
reached, not the real remaining pool. It closes exactly as a partial count —
18 alreadySkipped + 56 attempted + 124 excluded by `--only-unreachable` + 1 aborting = 199.

**Consequence: do not use an aborted run's `Eligible` line to size the remaining work.** Recompute
from `data/roster.json`. Cosmetic, deliberately not fixed today — flagging it beats changing the
stats object right after its first real firing.

## 1. The `lib/roster.ts` trim bug — FIXED. Commit `3965223`, pushed

The 08-27/09-02 notes had this as "lowercases but doesn't trim (`:107`, `:308`). Latent."
Confirmed latent and fixed anyway. Added `normalizeGenre()` (mirrors the existing
`normalizeCompany`), applied at the index side (`buildGenreIndex`), the query side
(`getArtistsByGenres`), and a third site the note hadn't flagged: **`getTopGenres` had the same
split** — it counted raw strings, so `"Pop"` and `"Pop "` would be two buckets, either of which
could fall out of the top-N alone. It now groups by the normalised key and returns the trimmed,
**display-cased** label (`'Pop'`, not `'pop'`), so the UI genre list is unchanged.

**Measured before touching anything:** `data/roster.json` has **636 distinct genre strings, zero
untrimmed, zero trim+lowercase collisions.** So this changes no behaviour on today's data. It is
hardening, and it is worth knowing that if a future roster import ever does introduce whitespace,
the pre-fix code would have dropped those artists from genre filters *silently*.

Two supporting facts found on the way:

- `lib/artistFit.ts:61` **already** did `.trim().toLowerCase()`. `roster.ts` was the inconsistent
  side, not the other way round.
- **Two comments already claimed the genre index trimmed, and were wrong** — `normalizeCompany`'s
  own doc comment in `lib/roster.ts`, and `selectSoleRouteArtists`'s in
  `scripts/backfill-genres.mjs` ("the same normalisation ... lib/roster.ts's genre index uses").
  The fix makes both true. The roster.ts one was reworded to point at `normalizeGenre`.

Tests: fixture artists now carry **deliberate** trailing-space slips (`'Rock '` on `Rock Band`,
and a new no-manager-email `Whitespace Genre Slip Artist` tagged `'Pop '`). That makes the
*pre-existing* Rock/Pop assertions fail if the normalisation is ever reverted, rather than only
the new ones. `npx tsc --noEmit` clean, `npx vitest run` **1081 passed / 45 files**,
`npm run build` clean.

**Correction to an earlier note:** the suite is **1081 tests**, not the "478 tests passing" the
