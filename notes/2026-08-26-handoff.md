## TWO CORRECTIONS TO THE 08-22 NOTE — read both before running anything

### 1. `--limit 60` was the wrong advice, and it is what lost the chunk

The 08-22 note said to size the chunk to the measured ~59-artist daily budget "so the run
ends near where the quota does." **That is precisely the failure mode.** The write happens
only after the last artist, so a chunk sized *at* the budget is near-guaranteed to spend the
whole day's quota and save none of it. That is now two consecutive days lost the same way
(19 artists on 08-22, 56 today).

Until the fix below lands, **do not size a chunk at the budget.** `--limit 40` completes
inside the budget and actually writes. It wastes about a third of the day's quota; that is
strictly better than losing all of it.

### 2. Exit code 0 does not mean the run succeeded

Today's run reported `exit code 0` despite aborting. The script *does* `process.exit(1)`
correctly — the run was piped through `tee`, and a shell pipeline reports the **last**
command's status, which was `tee` succeeding.

**Do not pipe the backfill through `tee`.** Background it and read the task output file
directly. Always read the tail of the actual output before believing a run finished.

## THE FIX — specified, briefed, NOT BUILT

**Decision (user, 2026-08-26): make the script write on abort.** Chosen over simply shrinking
the chunk, because it retires the whole class of loss — with it, chunk size stops mattering:
set a generous `--limit`, let the quota kill the run, and keep everything it earned.

### The obstacle

`backfillGenres` (exported, `scripts/backfill-genres.mjs:778`) throws
`SpotifyQuotaExhaustedError` out of its per-artist loop. `main()` catches it at ~`:1666-1683`,
prints `Aborting:` and exits — so the partial result dies with the stack and `main()` never
reaches its write path at ~`:1724-1764`.

### The shape to build

- In `backfillGenres`, catch `SpotifyQuotaExhaustedError` around the per-artist work, stop the
  loop, and **return the normal `{ artists, stats, log }` shape** with the work done so far
  plus `aborted: true` / `abortReason`.
- `main()` then takes its **normal path** — same summary, same roster write, same log write,
  no second write path. Afterwards, if aborted, print the message and `process.exit(1)`.
- Any error that is **not** `SpotifyQuotaExhaustedError` keeps today's behaviour exactly:
  propagate with full stack. Do not broaden that catch.

### Requirements — #2 is the dangerous one

1. Exit code stays **non-zero** on abort. A truncated run is not a successful run.
2. **Artists never attempted must NOT be logged as skipped.** They must stay eligible next
   run. A wrongly-recorded skip reason can *permanently* exclude an artist — see
   `PERMANENT_SKIP_REASONS`. This is the easiest thing to get wrong and the most damaging.
3. The artist that triggered the 429 was never evaluated — it must not be logged as a skip.
4. The log's `runs` entry must be honest that the run was partial.
5. The summary output must make truncation impossible to miss.
6. A dry run still writes nothing, aborted or not.
7. `--limit` semantics unchanged.

### Tests to add (`scripts/backfill-genres.test.mjs`, node:test)

- an aborted `--write` run **writes the fills completed before the abort** (the regression
  that would have saved today's 56),
- the aborting artist and all un-attempted artists are not logged as skipped and remain
  eligible on a later run,
- a non-quota error still propagates and writes nothing,
- an aborted dry run writes nothing.

Match the existing suite's fixtures/style. Do not weaken existing tests.

### Verify (do not trust a subagent's summary — re-run these)

`npx tsc --noEmit`, `npx eslint` on both touched files.

quota. Fakes/fixtures only.
