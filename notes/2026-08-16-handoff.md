## The core finding — read this first

The README describes Song Demos as pitching **"unsigned/independent"** artists' managers.
The bundled roster is nothing of the kind. Measured from `data/roster.json` (7,230 artists,
4,220 unique manager inboxes, generated 2026-08-08):

| Metric | Value |
|---|---|
| Artists under 50k Spotify followers | **0** |
| Median Spotify followers | 593,950 |
| p90 | 7,426,105 |
| Top manager domains | redlightmanagement.com (157), gmail.com (90), atcmanagement.com (23), threesixzero.com (23), rocnation.com, crushmusic.com |

There is no independent tier in this data. It is mid-to-major artists at the largest
management firms in the world, who receive unsolicited demos daily and have no structural
reason to open one. **No amount of tooling quality fixes this.** The engineering is good;
the list is the problem.

Derived segment worth targeting instead — artists at a ≤2-artist management company OR with
a manager on a freemail address, under 400k followers: **~1,098 artists / ~1,078 inboxes.**
That subset is what the new "Independent contacts only" filter selects.

Other measured facts that drove the work:

- 3,010 artists (41.6%) have `genres: []`, and `getArtistsByGenres` returned `[]` for an
  empty genre selection → **1,261 manager inboxes were unreachable** through the main funnel.
- 2,173 of 4,220 inboxes represent more than one artist; the largest covers 32.
- 1,960 of 2,666 management companies represent ≤2 artists.
- Radio: 155 stations / 161 addresses, **zero** music-director or programming addresses,
  19 are `news@`. 116 of 155 are "International" collapsed into one filter bucket despite
  the data carrying country granularity.

  render broken for every hand-added/CSV contact. Reasoning is comments in the file.

### 2. Reachability filters + empty-genre unlock
`lib/roster.ts`, `lib/demosSend.ts`, `app/api/preview/route.ts`, `useDemosFlow.ts`,
`AudienceFiltersPanel.tsx`, `DemosSection.tsx`, `types.ts`

### 3. Spam score rebuilt
`lib/spamScore.ts`, `SpamScoreBadge.tsx`, `AccountSection.tsx`

- The 0–100 numeric score is **gone** — output is `{ risk, issues[] }` with a severity each.
  The old weights (8 points a phrase, 6 a punctuation mark) implied a precision nobody could
  defend.
- Phrase list cut 33 → 16, all multi-word constructions. Dropped *free*, *amazing*,
  *instant*, *cash*, *urgent* etc., which fire on ordinary music copy. Regression tests
  assert "an amazing record" and "free to use the stems" no longer trigger.
- New checks: link-to-text ratio, unrecognized `{{variables}}`, near-textless body.
- **Correction to my brief:** I assumed the tool sent HTML-only mail. It does not —
  `mailSend.ts` sets `mailOptions.text` unconditionally before the `signOffImage` branch
  touches `.html`. The agent verified this and correctly declined to add the check. Noted in
  the file header so it is not "fixed" again later.
- DMARC now renders as its own red/green card above SPF/DKIM/MX with plain-English
  consequences. DKIM wording avoids accusing a correctly-configured domain, since the route
  only probes 10 fixed selectors and can prove presence but never absence.

### 4. Tier-segmented analytics
`lib/roster.ts`, new `app/api/roster-tiers/route.ts`, `utils.ts`, `OverviewSection.tsx`, `types.ts`

Answers "does reply rate collapse as artist/company size goes up?" — the question that
settles the core finding empirically.

- Built as a **retroactive join** of campaign addresses against the roster, not recorded at
  send time. This was a deliberate design call: it needs no send-path change and works on
  **existing** campaign history, so there is an answer immediately rather than in months.
  Do not trade that property away.
- Bands: Under 250K / 250K–1M / 1M–5M / 5M+ (chosen against the real distribution; the
  existing generic tiers would put everything in one bucket).
- Shared inbox takes the **max** follower count across its artists — a manager repping one
  small act and one headliner is a headliner's triaged inbox.
- Addresses with no roster match → explicit "Unknown (not in roster)" bucket, never dropped.
- `MIN_TIER_SAMPLE_SIZE = 5`; rows below it are dimmed with the denominator always shown, so
  a 1-of-1 reply cannot read as "100%".
- Known imprecision, documented in the UI: the roster drifts between refreshes, so this is
  "tier as the roster currently describes it", not "as it was at send time".

### 6. Spotify genre backfill script — WRITTEN BUT NOT RUN
`scripts/backfill-genres.mjs` + `scripts/backfill-genres.test.mjs` (21 tests pass)

**This has never been executed against real data. `data/roster.json` is untouched.**
That was deliberate — given the pipeline's history of silently destroying 1,745 contacts,
an agent should not be the first thing to run it.

- Dry-run by default; `--write` required to modify anything.
- Merge-only, never replaces; never overwrites a non-empty `genres` array; never touches
  `managerEmails` / `managerNames`.
- Requires exact case-insensitive name match **and** a follower-count sanity check before
  accepting genres, because Spotify name search is fuzzy.
- Genre vocabulary can never grow — Spotify tags are normalized and mapped into the existing
  ROSTR vocabulary (plus a 4-entry alias table); unmapped tags are reported, not added.

## Incident worth remembering: the two agents that contradicted each other

Agent 1 shortened the default templates to ~20 words. Agent 3 independently added a
link-to-text-ratio check to the spam scorer. Both were correct in isolation. Run together,
**all three shipped default templates flagged HIGH risk against the shipped checker** —
a new user would open the app and find every built-in template red.

```
DEMOS    — 22 words → HIGH
FOLLOWUP — 26 words → HIGH
RADIO    — 15 words → HIGH
```

Root cause was my instruction to agent 1 to keep it short. Resolved by lengthening the
templates to ~70 words, since a 20-word body wrapped around a bare Drive link genuinely is
the canonical spam shape.

`app/dashboard/constants.test.ts` now asserts the shipped defaults never trip our own
checker, so this cannot silently recur. **Lesson: parallel agents with disjoint files can
still produce incoherent output at the seam. Check integration, not just each diff.**
