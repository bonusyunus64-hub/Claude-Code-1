# rostr.cc Data Pipeline — Agent Context

This document is a briefing for an AI agent working on the TrackPitch roster data pipeline.
Read this before touching any roster-related code or data files.

---

## What the pipeline is

rostr.cc does NOT have a public API and does NOT allow automated scraping.
Data is obtained by **manually exporting from the rostr.cc web UI as XLSX**, then running
`scripts/parse-roster.mjs` locally to produce `data/roster.json`.

There is no live web scraper. No Puppeteer. No Playwright. No fetch loops hitting rostr.cc.
The entire pipeline is: export XLSX → run parse script → JSON written to disk.

---

## The two files you care about

| File | Purpose |
|------|---------|
| `data/roster_new.xlsx` | Raw export from rostr.cc — the source of truth, replace this when refreshing |
| `data/roster.json` | Parsed output — what the app reads at runtime, regenerated by the parse script |
| `scripts/parse-roster.mjs` | The parser — reads the XLSX, writes the JSON |

---

## Running the parser

```bash
node scripts/parse-roster.mjs
```

No env vars needed. Output goes straight to `data/roster.json`.
The script prints a summary: total artists, unique genres, artists-with-emails count.

Current roster (last import): **7,975 artists**, 2,983 with manager emails, 709 unique genres.

## The XLSX column requirements

The parser reads these exact column header names (case-sensitive).
If rostr.cc renames a column in a new export, the field silently becomes empty — check the
summary counts after every import.

| XLSX column | JSON field | Notes |
|-------------|-----------|-------|
| `Artist Name` | `name` | Required — rows without this are dropped |
| `ROSTR URL` | `rostrUrl` | e.g. `https://www.rostr.cc/artists/brunomars` |
| `Genre` | `genres[]` | Comma-separated in the cell, split into array |
| `Type` | `type` | `Person` / `Group` / `Non-artist` |
| `Gender` | `gender` | `MALE` / `FEMALE` / empty |
| `Spotify Followers` | `spotifyFollowers` | Integer, 0 if missing |
| `Instagram Followers` | `instagramFollowers` | Integer, 0 if missing |
| `YouTube Subscribers` | `youtubeSubscribers` | Integer, 0 if missing |
| `Management Company` | `managementCompany` | Free text |
| `Agencies` | `agencies` | Free text |
| `Labels` | `labels` | Free text |
| `Publishers` | `publishers` | Free text |
| `Manager Email(s)` | `managerEmails[]` | Semicolon-separated, split into array |
| `Manager Name(s)` | `managerNames[]` | Semicolon-separated, split into array |
| `Instagram Handle` | `instagramHandle` | e.g. `@brunomars` |
| `Avatar URL` | `avatarUrl` | Spotify CDN URL (`i.scdn.co/image/...`) |

## How to export from rostr.cc

rostr.cc requires a paid subscription to access contact data.

1. Log in at rostr.cc
2. Go to the Artists section
3. Apply any filters you want (genre, country, follower range, etc.)
4. Use the **Export** button — select XLSX format
5. Make sure ALL the column headers above are included in the export settings
6. Save the file as `data/roster_new.xlsx` (overwrite the existing one)
7. Run `node scripts/parse-roster.mjs`

**Export limits:** rostr.cc typically caps single exports at a few thousand rows.
If your filtered set is large, export in batches (e.g. by genre or region) and
merge the XLSX files before running the parser, or run the parser on each batch
and merge the resulting JSON arrays manually.

**Merging XLSX batches before parsing:**
The easiest way is to open both files in Excel/Numbers, copy all rows from sheet 2
(excluding the header row) and paste into sheet 1, then save as `roster_new.xlsx`.

## Data quality notes

- **Emails**: ~37% of artists in the current roster have manager emails. Rows without emails
  still appear in `roster.json` and are used for non-email features (genre filtering, stats).
  If you're filtering for outreach campaigns, always filter by `managerEmails.length > 0`.

- **Genres**: Some artists have an empty `genres: []` array even in the raw export.
  This is a gap in the rostr.cc data, not a parsing bug. Genre filtering in the app
  handles empty arrays gracefully.

- **avatarUrl**: Points to Spotify CDN (`i.scdn.co`). These URLs do not expire quickly
  but are not permanent — they can go stale months after export. The app renders them
  as `<img>` tags with no fallback, so broken avatars just show blank.

- **managerNames / managerEmails pairing**: The arrays are index-matched but rostr.cc
  sometimes has mismatched counts (3 names, 2 emails). The parser splits them
  independently — do not assume `managerNames[i]` corresponds to `managerEmails[i]`.

- **Duplicates**: If you merge batch exports, watch for duplicate artists (same name,
  same rostrUrl). The parser does not deduplicate. Add a dedup step if merging:
  ```js
  const seen = new Set();
  const deduped = artists.filter(a => {
    if (seen.has(a.rostrUrl)) return false;
    seen.add(a.rostrUrl);
    return true;
  });
  ```

## Spotify enrichment (separate, optional)

The app has a live Spotify URL lookup via `/api/spotify-artist`. This is NOT part of the
parse-roster pipeline — it runs on-demand per artist when the UI renders a campaign.

- Uses Client Credentials OAuth (no user login), token auto-refreshes
- Results cached in Upstash Redis: key `trackpitch:spotifyUrl:<lowercased-name>`
- Sentinel value `""` (empty string) = "we searched, found nothing" — skips re-querying
- Rate limit: Spotify's Client Credentials tier is generous (~180 req/min). The app
  queries one artist at a time, so this is not a concern in normal use.
- If you need to bulk-enrich the roster offline, the `findArtistUrl(name)` function
  in `lib/spotify.ts` is the right entry point. Add 300–500ms between calls to stay
  well under Spotify's limits.

Spotify env vars required:
```
SPOTIFY_CLIENT_ID=...
SPOTIFY_CLIENT_SECRET=...
```

## What NOT to do

- Do not write a scraper that fetches rostr.cc pages via HTTP — their ToS prohibits it
  and they will block the IP quickly.
- Do not commit `data/roster_new.xlsx` to git — it contains real PII (manager emails).
  It is gitignored. Keep it local only.
- Do not commit `data/roster.json` if you've added real contact data you didn't have
  before — check what's already tracked before staging.
- Do not run `node scripts/parse-roster.mjs` if `data/roster_new.xlsx` doesn't exist —
  the script will crash. The file is not in the repo.

## Quick-reference commands

```bash
# Re-parse after dropping a new XLSX into data/roster_new.xlsx
node scripts/parse-roster.mjs

# Spot-check the output
node -e "
const r = require('./data/roster.json');
console.log('Artists:', r.artists.length);
console.log('With emails:', r.artists.filter(a => a.managerEmails.length).length);
console.log('Genres:', r.genres.length);
console.log('Sample:', JSON.stringify(r.artists[0], null, 2));
"

# Find artists missing emails (to gauge how much contact data the export has)
node -e "
const r = require('./data/roster.json');
const noEmail = r.artists.filter(a => !a.managerEmails.length);
console.log('No email:', noEmail.length, 'of', r.artists.length);
"

# Check for duplicate rostrUrls (after merging batch exports)
node -e "
const r = require('./data/roster.json');
const urls = r.artists.map(a => a.rostrUrl).filter(Boolean);
const dupes = urls.filter((u, i) => urls.indexOf(u) !== i);
console.log('Duplicate rostrUrls:', dupes.length);
if (dupes.length) console.log('Examples:', dupes.slice(0, 5));
"
```
